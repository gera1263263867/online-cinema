# Online Cinema Analytics

Movie Service → Kafka → ClickHouse → Aggregation Service → PostgreSQL → S3.
Grafana читает материализованные агрегаты из ClickHouse.

## Запуск

```sh
docker compose up
```

Compose сам создаёт топик, регистрирует Avro-схему и применяет миграции. Генератор наполняет витрину историческими событиями за 12 дней и затем добавляет новые сессии. Сборка и несколько JVM требуют свободной памяти. Рекомендуется выделить Docker Desktop от 6 ГБ.

- [Swagger продюсера](http://localhost:8000/docs)
- [Swagger агрегации](http://localhost:8001/docs)
- [Swagger экспорта](http://localhost:8002/docs)
- [Дашборд Grafana](http://localhost:3000/d/online-cinema)
- [Консоль MinIO](http://localhost:9001), локальные логин/пароль — `cinema_local` / `cinema_local_password`

## HTTP API

```sh
curl -fsS -X POST http://localhost:8000/events \
  -H 'Content-Type: application/json' \
  -d '{"user_id":"u-1","movie_id":"m-1","event_type":"VIEW_STARTED","timestamp":"2026-11-25T12:00:00Z","device_type":"TV","session_id":"s-1","progress_seconds":0}'
```

Ответ — HTTP 201 и `event_id`. Можно передать собственный UUID и повторить запрос с тем же UUID и теми же полями. Ошибка валидации возвращает 422, ошибка публикации после повторов — 503.

Пересчёт и экспорт за выбранную дату (UTC):

```sh
curl -fsS -X POST http://localhost:8001/aggregate/2026-11-25
curl -fsS -X POST http://localhost:8002/export/2026-11-25
```

`AGGREGATION_INTERVAL` и `EXPORT_INTERVAL` задают интервалы в секундах. По умолчанию 120 и 300. Экспорт начинается с предыдущего дня, повторяет выгрузку семи предшествующих дней и перезаписывает `s3://movie-analytics/daily/YYYY-MM-DD/aggregates.json`. Повторы позволяют сохранить обновлённый D7.

## Данные и гарантии

- Топик `movie-events` имеет три партиции, три реплики и `min.insync.replicas=2`. Три совмещённых узла KRaft сохраняют кворум при отказе одного узла. Продюсер использует `acks=all` и ключ `user_id`, чтобы Kafka сохраняла порядок записи событий пользователя в одной партиции.
- Схема `schemas/movie-event.avsc` регистрируется под subject `movie-events-value`. Schema Registry назначает версию 1 при первой регистрации. Сообщение содержит идентификатор именно той версии схемы, которой продюсер сериализовал payload. UUID, UTC-время с миллисекундами и перечисления определены в Avro.
- Kafka Engine разбирает `AvroConfluent`. Materialized View переносит события в `ReplacingMergeTree` с партициями по UTC-месяцу и сортировкой по UTC-дню и UUID. Запросы к событиям используют `FINAL` для дедупликации повторной доставки того же события.
- DAU считает каждого пользователя, у которого было событие в день расчёта. Топ фильмов ранжирует фильмы по числу стартов. Среднее время просмотра учитывает завершения. Конверсия — отношение числа завершений к числу стартов за день. При нулевом знаменателе значение отсутствует.
- Когорта определяется первым `VIEW_STARTED` пользователя. Возврат — любое событие пользователя на соответствующий календарный день UTC. Незрелые дни и пустые когорты имеют `NULL`. SQL считает всю матрицу D0–D7, поэтому отдельные D1/D7 доступны в PostgreSQL и S3.
- ClickHouse атомарно заменяет дневную партицию метрик. PostgreSQL заменяет набор за день одной транзакцией под блокировкой, включая удаления из изменившегося топа. Общей транзакции у двух БД нет. Повторный запуск пересчитывает и восстанавливает оба снимка при частичном сбое.
- MinIO предназначен для демонстрации локально. Привязанные к хосту порты доступны только через loopback.

## Интеграционный тест

```sh
docker compose run --build --rm test
```

Compose запускает зависимости. Тест проверяет HTTP-валидацию, публикует событие с уникальным UUID через HTTP, опрашивает ClickHouse и сравнивает все восемь полей. У каждого запуска свой UUID и пользователь. GitHub Actions запускает ту же команду на чистом runner.

После старта системы можно остановить один брокер командой `docker compose stop kafka2` и запустить тест без перезапуска зависимостей — `docker compose run --no-deps --rm test`. Для восстановленного кластера выполните `docker compose start kafka2`.
